# 游戏流程与状态机

本文档描述引擎（上帝 / God）如何一步步推进一局游戏。每个 **Phase（阶段）**都对应
`werewolf/engine.py` 中的一个处理函数，并且会向对应的 agent 索要一个**结构化动作（Action）**。

---

## 1. 总览：一局游戏的骨架

```
开局
 │
 ├─ 发牌（12 份身份） ──────────────► 生成 12 份个人视角 + 1 份狼队视角
 │
 ▼
第 1 夜  NIGHT
 ├─ N1 狼人频道讨论      WOLF_CHAT        [狼人可见]
 ├─ N2 狼人击杀投票      WOLF_KILL        [狼人可见]
 ├─ N3 女巫行动          WITCH            [女巫可见]
 ├─ N4 预言家查验        SEER             [预言家可见]
 └─ N5 猎人状态告知      HUNTER_NOTIFY    [猎人可见]
 │
 ▼
第 1 天  DAY
 ├─ D0 天亮公布死讯      DAWN             [公开]
 ├─ D1 首夜死者遗言      LAST_WORDS       [公开]      ← 仅第 1 天
 ├─ D2 警长竞选          SHERIFF_*        [公开]      ← 仅第 1 天
 ├─ D3 依次发言          DAY_SPEECH       [公开]
 ├─ D4 投票放逐          DAY_VOTE         [公开]
 ├─ D5 出局者遗言        LAST_WORDS       [公开]
 └─ D6 猎人开枪 / 白痴翻牌 HUNTER_SHOT     [公开]
 │
 ▼
胜负结算 ── 未结束 ──► 第 2 夜 …（循环）
 │
 ▼
结束：好人胜 / 狼人胜
```

---

## 2. 夜晚详细流程

上帝口令：**「天黑请闭眼。」**

### N1 — 狼人频道讨论 `WOLF_CHAT`
- 所有**存活狼人**按座位号升序，每人发言 1 轮（可配置轮数 `wolf_chat_rounds`，默认 1）。
- 发言内容进入**狼队视角**（`audience = WOLVES`），好人永远看不到。
- 每次发言同时附带一个**刀人意向** `kill_suggestion`（可为 `null` 表示还没想好）。
- 首夜额外：上帝告知所有狼人彼此的座位和身份。

**Action schema**
```json
{ "speech": "……我觉得 3 号像预言家，建议今晚刀 3。",
  "kill_suggestion": 3 }
```

### N2 — 狼人击杀投票 `WOLF_KILL`
- 每名存活狼人提交一个击杀目标（或 `null` = 空刀）。
- 统计票数：票数最高者被刀；平票时由**座位号最小的存活狼人**（狼队长）拍板。
- 若多数选择 `null`，则为**空刀**（平安夜的来源之一）。
- 结果记入狼队视角与上帝日志，**好人看不到**。

**Action schema**
```json
{ "target": 3 }        // 或 { "target": null } 表示空刀
```

### N3 — 女巫行动 `WITCH`
上帝告知女巫：
1. 今晚被刀的是几号（若配置为 `first_night_only` 则仅首夜告知）
2. 解药 / 毒药的剩余状态

女巫一次提交两个决定：
- `heal`: 是否对刀口使用解药
- `poison`: 毒杀目标座位号，或 `null`

约束（引擎强制校验，非法动作会被拒绝并要求重来，重试 2 次后视为弃权）：
- 解药已用过 → `heal` 必须为 `false`
- 毒药已用过 → `poison` 必须为 `null`
- 今晚无人被刀 → `heal` 必须为 `false`
- 第 2 夜起，刀口是女巫自己 → `heal` 必须为 `false`（不能自救）
- `heal=true` 且 `poison != null` → 违反"同夜只能用一瓶药"

**Action schema**
```json
{ "heal": true, "poison": null }
```

### N4 — 预言家查验 `SEER`
- 预言家选择一名存活且未验过的玩家。
- 上帝立即返回结果 `狼人` / `好人`，写入预言家的**个人私有日志**。

**Action schema**
```json
{ "target": 7 }
```

### N5 — 猎人状态告知 `HUNTER_NOTIFY`
- 不需要 agent 动作，上帝向猎人的私有日志写入一条 `你当前可以开枪 / 不可开枪`。
- 该状态由"是否被女巫毒"决定，在结算时才真正确定，因此这一步只写入一个**提示性**状态。

## 3. 白天详细流程

上帝口令：**「天亮了。」**

### D0 — 天亮公布死讯 `DAWN`
- 结算夜间死亡：`狼刀目标`（若未被救）+ `女巫毒杀目标`。
- 公布格式（公开事件）：
  - 有人死亡：`昨晚，3 号、8 号 倒牌出局。`（按座位号升序，**不公布身份、不公布死因**）
  - 无人死亡：`昨晚是平安夜。`
- 立即进行一次胜负判定。

### D1 — 遗言 `LAST_WORDS`
- 第 1 天：首夜所有死者按座位号升序各留一次遗言。
- 第 2 天起：夜间死亡**无遗言**，直接进入发言。
- 被投票放逐者：任何一天都有遗言。

### D2 — 警长竞选 `SHERIFF_*`（仅第 1 天）
```
SHERIFF_SIGNUP   所有存活玩家同时决定是否上警
       ↓
SHERIFF_SPEECH   上警玩家按座位号升序依次发言（可在发言中宣布退水）
       ↓
SHERIFF_VOTE     未上警且未退水的玩家投票（上警者无票）
       ↓
  ├─ 唯一最高票 → 当选警长
  ├─ 平票 → SHERIFF_PK（平票者再发言一轮）→ 再投票
  └─ 再平票 → 警徽流失，本局无警长
```
- 若无人上警 或 所有人都上警 → 警徽流失。

### D2.5 — 自爆随时可能打断白天 `EXPLODE`

狼人在**任何一次发言**里都可以把 `explode` 置为 `true`（好人的动作里根本没有这个字段）。
一旦发生：

```
DAY_SPEECH / SHERIFF_SPEECH / PK 发言
        │
        ├── 某个狼人 explode=true
        │        ↓
        │   ① 他这句话仍然公开记录（自爆前往往会留一句）
        │   ② 亮明狼人身份，立刻出局，revealed_role = WEREWOLF
        │   ③ 若是警长 → 警徽当场销毁
        │   ④ 抛出 DayInterrupted
        │        ↓
        └──► 白天立即结束：后续发言取消、今天不投票、没有遗言
                 ↓
             直接进入下一个黑夜
```

引擎里用一个 `DayInterrupted` 异常实现，在主循环 `try/except` 掉。
警上发言阶段自爆会额外把 `sheriff_status` 置为 `lost`，本局不再有警长。

### D3 — 依次发言 `DAY_SPEECH`
- **发言起点与方向**：
  - 有警长：警长决定从自己的**上家**（座位号 -1）还是**下家**（座位号 +1）开始，绕圈一周，警长**最后发言**。
  - 无警长：从"昨夜死者的下一位存活玩家"开始，座位号递增方向绕圈。第 1 天若为平安夜，则从 1 号开始。
- 每名存活玩家发言 1 轮。发言是**公开事件**，所有人（含已死亡的观察者）都能看到。
- 发言除自然语言外还携带**结构化元信息**，用于引擎统计和让 heuristic agent 可读：

**Action schema**
```json
{
  "speech": "我是预言家，昨晚验的 7 号是查杀。",   // 有字数上限，默认 450 字
  "claim": "SEER",                 // 公开宣称的身份，null 表示不起跳
  "claim_detail": "验 7 号查杀",    // 附加说明（验人结果、警徽流等）
  "claimed_check": {"target": 7, "result": "WOLF"},  // 结构化的验人宣称
  "suspects": [7, 11],             // 本轮怀疑的座位
  "trusts": [2],                   // 本轮信任的座位
  "explode": false                 // ★ 仅狼人有这个字段，true = 自爆
}
```

> **发言字数上限**：默认 450 字 ≈ 真人讲 2 分钟。超长会被判为非法并要求重说
> （不是截断），让 agent 自己学会取舍重点。
> `claim` 是**玩家自称**，引擎不做真假校验——撒谎是游戏的一部分。
> 引擎只把它当作公开信息记录下来，供其他 agent 判断。

### D4 — 投票放逐 `DAY_VOTE`
- 所有有投票权的存活玩家同时投票（引擎按座位号顺序收集，但**投票内容在全部收齐前互相不可见**）。
- 收齐后一次性公开所有票型：`3→7, 5→7, 7→3, …`
- 计票：警长 1.5 票，白痴翻牌后 0 票，其余 1 票。
- 平票 → `DAY_VOTE_PK`（平票者发言一轮）→ 非平票者重新投票 → 仍平票则平安日。

**Action schema**
```json
{ "target": 7, "reason": "他的发言前后矛盾" }   // target=null 表示弃票
```

### D5 — 放逐者遗言 `LAST_WORDS`
**Action schema**
```json
{ "speech": "我是女巫，解药给了 3 号，剩下的交给你们了。" }
```

### D6 — 猎人开枪 / 白痴翻牌 `HUNTER_SHOT` / `IDIOT_REVEAL`
- 若出局者是**猎人**且死因允许开枪 → 索要开枪目标。
- 若出局者是**白痴** → 翻牌，不死，当天不再有人出局，直接进入黑夜。

**Action schema**
```json
{ "target": 11 }   // null 表示不开枪
```

## 4. 胜负结算时机

引擎在以下每个时刻调用 `check_winner()`：
1. 夜晚结算完成（DAWN 公布死讯后）
2. 投票放逐生效后
3. 猎人开枪生效后
4. 白痴翻牌后（白痴不死，但流程要检查）

## 6. 非法动作的处理

Agent 返回的动作先经过 `actions.validate()`：
1. **JSON 解析失败** → 重试，仍失败则取**默认安全动作**。
2. **目标非法**（死人、不存在、已验过、违反用药规则、发言超长）→ 把错误信息回灌给 agent 重试。
3. 用尽迭代次数 → 使用**默认安全动作**：
   | Action | 默认值 |
   |---|---|
   | `wolf_chat` | 空发言，无意向 |
   | `wolf_kill` | 随机一名非狼存活玩家 |
   | `seer_check` | 随机一名未验过的存活玩家 |
   | `witch_action` | 不用药 |
   | `speech` / `last_words` | `"（该玩家没有发言）"` |
   | `vote` | 弃票 |
   | `hunter_shoot` | 不开枪 |
   | `sheriff_signup` | 不上警 |

所有非法动作和回退都会写入上帝日志（`audience = GOD`），复盘时可见。

### 迭代上限 `max_iterations`

**agent 的思考长度不受任何限制**（LLM 后端用 adaptive thinking，`max_tokens` 给到 16K），
但**同一个决策点最多向 agent 索要 `max_iterations` 次动作**（默认 3 次，含第一次）。
每次失败都会把具体错误回灌给 agent 让它自己修正：

```
第 1 次 → 非法（"target=9 不是合法目标，可选：[1,2,3...]"）
第 2 次 → 非法（"发言太长了：612 字，上限 450 字"）
第 3 次 → 合法 ✓          ← 用尽则走安全回退，流程永不卡死
```

这样既不压制 agent 的推理深度，又保证一局游戏有确定的上界、不会因为某个 agent
反复出错而卡死或无限烧 token。

### 心路历程 `private_thought`

每个动作都可以带一个 `private_thought` 字段。引擎会在校验前把它**摘出来**，
写进 `state.thought_log` 和一条 `audience = GOD` 的事件。

- 它**不限长度**（不像 speech 有 450 字上限）
- 它**绝不会进入任何玩家的视角**——测试对此有专门断言
- 它只出现在复盘的「心路历程」一章里

被判非法的尝试也会记录（带 `accepted: false` 和错误原因），所以复盘里能看到
agent 是怎么自我修正的。
