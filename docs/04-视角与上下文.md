# 视角与上下文规范：12 份个人视角 + 1 份狼队视角

这是本项目最核心的一份规范。**"agent 能看到什么"就等于"agent 是谁"**——
一个拿到狼队视角的 agent 就是狼，一个只拿到公开信息的 agent 就是平民。

---

## 0. 一共有多少份上下文？

| 编号 | 视角 | 份数 | 持有者 |
|---|---|---|---|
| ① | 个人视角 `PlayerView` | **12** | 每个座位一份，互不相同 |
| ② | 狼队视角 `WolfTeamView` | **1** | 4 名狼人**共享同一份**，作为区块挂在他们的个人视角上 |

所以任意时刻系统里存在 **12 + 1 = 13** 份上下文。
好人的个人视角里 `wolf_team` 字段恒为 `null`——不是被隐藏，是**根本没有被构造**。

---

### 1.2 `role_knowledge` 按角色的差异

这是 12 份视角**真正不同**的地方：

| 角色 | `role_knowledge` 内容 |
|---|---|
| `VILLAGER` 平民 | `{}` — 平民没有任何私有信息，视角里只有公开信息 |
| `SEER` 预言家 | `checks`（每晚验人结果）、`unchecked_alive`（还没验过的存活玩家） |
| `WITCH` 女巫 | `has_antidote` / `has_poison`、`tonight_victim`（今晚刀口，仅夜晚）、`potion_log`（用药记录） |
| `HUNTER` 猎人 | `can_shoot`（当前是否能开枪） |
| `IDIOT` 白痴 | `revealed`（是否已翻牌）、`can_vote` |
| `WEREWOLF` 狼人 | `teammates`（4 名狼队友的座位）、`alive_teammates`，并**额外挂载 `wolf_team` 区块** |

### 1.3 12 份视角的信息量对比（开局时）

| 座位 | 角色 | 知道自己身份 | 知道队友 | 私有信息流 | 共享频道 |
|---|---|---|---|---|---|
| 4 个座位 | 狼人 | ✓ | ✓ 3 名队友 | 刀人结果 | ✓ 狼队频道 |
| 1 个座位 | 预言家 | ✓ | ✗ | 每晚 1 条验人结果 | ✗ |
| 1 个座位 | 女巫 | ✓ | ✗ | 每晚刀口 + 药状态 | ✗ |
| 1 个座位 | 猎人 | ✓ | ✗ | 开枪状态 | ✗ |
| 1 个座位 | 白痴 | ✓ | ✗ | 翻牌状态 | ✗ |
| 4 个座位 | 平民 | ✓ | ✗ | 无 | ✗ |

## 2. 狼队视角 `WolfTeamView`（×1）

4 名狼人**共享同一个对象**。它是狼人相对好人的全部信息优势。

```jsonc
{
  "view_type": "wolf_team",
  "generated_at_seq": 87,

  // 狼队花名册（开局即完全已知）
  "roster": [
    {"seat": 4,  "name": "4号",  "alive": true},
    {"seat": 7,  "name": "7号",  "alive": true},
    {"seat": 10, "name": "10号", "alive": false, "died_day": 1, "died_by": "exiled"},
    {"seat": 12, "name": "12号", "alive": true}
  ],
  "alive_wolves": [4, 7, 12],
  "dead_wolves":  [10],

  // 狼队频道：每晚的内部讨论，好人永远看不到
  "chat_log": [
    {"day": 1, "seat": 4,  "text": "3号位置好，明天容易起跳预言家，建议刀 3。",
     "kill_suggestion": 3},
    {"day": 1, "seat": 7,  "text": "我觉得先刀 8 号，他像女巫。", "kill_suggestion": 8},
    {"day": 1, "seat": 10, "text": "听队长的，刀 3。", "kill_suggestion": 3},
    {"day": 1, "seat": 12, "text": "同意刀 3。", "kill_suggestion": 3}
  ],

  // 每晚的刀人决议全过程
  "kill_history": [
    {"day": 1, "votes": {"4": 3, "7": 8, "10": 3, "12": 3},
     "decided": 3, "decided_by": "majority", "outcome": "saved_by_witch"},
    {"day": 2, "votes": {"4": 9, "7": 9, "12": 9},
     "decided": 9, "decided_by": "majority", "outcome": "died"}
  ],

  // 狼队根据**可观测信息**推导出的战场态势（由引擎自动维护，非狼人手填）
  // 注意：这里绝不含上帝信息。狼人不知道谁是神、谁是民。
  "intel": {
    "_source_note": "本区块所有字段都由狼人可观测的公开信息或己方行动结果推导，不含上帝信息。",
    "claimed_roles":  {"2": "SEER", "3": "SEER", "9": "WITCH"},   // 公开发言里的自称
    "claimed_seers":  [2, 3],          // 场上所有起跳预言家的座位
    "our_claimed_gods": [3],           // 我方悍跳了神职的队友
    "golden_waters":  {"5": [2]},      // 谁被谁发了金水（来自公开发言）
    "checks_on_us":   [{"day": 1, "by": 2, "target": 7, "result": "WOLF"}],  // 我方被公开查杀
    "witch_antidote_used": true,       // 来源：我们刀了 3 号但天亮没死 → 一定被解药救了
    "witch_poison_used":   false,      // 来源：天亮死的人数 == 我们刀的人数 → 没人被毒
    "alive_wolf_count": 3,
    "alive_good_count": 7,
    "suspected_god_seats": [2, 9, 5],  // 只按「公开起跳/已翻牌/被发金水」排序的屠边优先级
    "edge_hint": "好人还剩 7 人，其中 3 人公开表现得像神。屠边只需杀光 4 神或 4 民其中一边。"
  },

  // 狼队战术板：狼人可以在每次发言时更新，跨夜持久
  "strategy_board": {
    "tonight_target":   9,
    "protect":          [4],           // 需要保的队友（比如已经拿到信任的倒钩狼）
    "push_target":      5,             // 白天要抗推的好人
    "notes": "12号第一天划水太明显，明天让他归票 5 号找补。"
  }
}
```

### 2.1 狼队视角的关键性质

1. **共享但不越权**：狼队视角里**没有**任何好人的真实身份。狼人只知道"我们 4 个是狼"，
   剩下 8 人在他们眼里也是黑的。预言家是谁、女巫是谁，狼人只能靠公开发言去推。
2. **`intel` 是引擎替狼人做的算术，不是作弊**：每一条都只来自狼人真实能观测到的东西 ——
   公开发言、公开票型、以及"我们自己刀了谁 / 天亮谁死了"这本只有狼人对得上的账。
   典型例子：`witch_antidote_used` 来自"我们刀了 3 号但天亮 3 号没死"。
   **特别注意**：`intel` 里**没有**"还剩几个神、还剩几个民"这种字段 —— 那是上帝信息，
   狼人不知道好人里谁是神谁是民，只能用 `suspected_god_seats`（纯粹按公开起跳排序）去猜。
3. **死狼仍然在频道里**：已出局的狼人看得到后续狼队频道（符合真实桌游"狼死了也知道队友是谁"），
   但**不能再行动**（不参与刀人投票、不发言）。
4. **`strategy_board` 是狼人自己写的**：由狼人在 `wolf_chat` 动作里更新，引擎只做存储，
   这给了 LLM 狼人一个跨夜的"共享记忆体"。

### 1.4 发言档案 `speech_archive` —— 为什么要单独存一份

真人玩家抓狼靠的是"**你第一天说过 X，第二天说过 Y，你自己圆一下**"。
要做到这件事，agent 必须随时拿得到**发言原文**，而不只是"谁自称什么"这种标签。

早期版本这里有个真 bug：发言只在事件增量里发一次，LLM 的对话历史一裁剪（第 24 轮之后）
就永久丢失了第一天的发言，而局势摘要里只有身份宣称和最近两轮票型、**没有任何发言原文**。
结果就是 agent 只能靠标签推理，根本打不出真人那种盘逻辑，对局读起来很假。

现在的做法：

- `state.speech_log` 存全部公开发言的原文（含 claim / 验人宣称 / 警徽流 / 怀疑 / 信任）
- `speech_archive` 是它的公开投影，**每回合都完整重发**，不依赖对话历史
- 近 **2 天**给**原文**，更早的压成一行立场摘要（跨天矛盾靠立场变化就能抓，能把上下文控住）
- 它是公开信息，所以 12 份个人视角里的这一块**完全相同**

## 3. 渲染成 LLM prompt

`prompts.py` 把上面的 JSON 渲染成给 LLM 的文本。渲染遵循三条原则：

1. **system 稳定**：规则全文 + 我的身份卡 + 输出格式，整局**逐字不变**，用于命中 prompt cache。
2. **增量 user**：每回合只发"自上次决策以来的新事件"+ 当前公开状态摘要 + 本次要做的动作。
3. **结构化输出**：用 `output_config.format` 的 JSON Schema 约束返回值，不靠"请输出 JSON"这种软约束。

渲染样例（预言家第 2 天发言）：

```
════════ 你的身份 ════════
你是 3 号玩家，身份是【预言家】，属于【好人阵营】。
胜利条件：把 4 名狼人全部票出局。
你的验人记录：
  第1夜 验 7 号 → 【狼人】(查杀)
  第2夜 验 2 号 → 【好人】(金水)
还没验过的存活玩家：1, 4, 5, 6, 9, 10, 12

════════ 场上局势（第 2 天 白天）════════
存活：1 2 3 4 5 6 7 9 10 12     出局：8(第1夜) 11(第1天被票)
警长：5 号
公开起跳：2 号自称预言家（验7号查杀）／ 3 号自称预言家（验7号查杀）／ 9 号自称女巫
第1天票型：1→7, 2→11, 3→11, 4→11, 5弃票 …（11 号被票出，翻牌白痴）

════════ 新增事件 ════════
[第2天 天亮] 上帝：昨晚，无人死亡（平安夜）。
[第2天 发言] 6号：我觉得 2 号和 3 号里有一个是狼，先听后面的。
[第2天 发言] 7号：我是平民，被 2 号和 3 号一起查杀我很冤。

════════ 轮到你了 ════════
现在是第 2 天的发言阶段，你是第 4 个发言的。
请输出你的发言和结构化判断。
```

## 4. 信息隔离的测试保证

`tests/test_visibility.py` 在每局结束后对**全部 13 份视角**做断言：

| # | 断言 |
|---|---|
| 1 | 任何非狼玩家的 `timeline` 里不含任何 `audience=WOLVES` 的事件 |
| 2 | 任何玩家的 `timeline` 里不含 `visible_to` 不包含自己的 `PRIVATE` 事件 |
| 3 | 任何玩家的 `timeline` / `public_state` 里不含别人的真实 `role`（除白痴翻牌等规则性公开） |
| 4 | 好人的 `wolf_team` 恒为 `None` |
| 5 | `WolfTeamView.roster` 只含 4 名狼人，不含任何好人的身份信息 |
| 6 | 投票阶段收齐前，任何人的视角里看不到别人已经投了谁 |
| 7 | 预言家 A 的验人结果不出现在预言家以外任何人的视角里 |
| 8 | 女巫的刀口告知不出现在女巫以外任何人的视角里 |

跑 200 局随机对局，逐帧检查所有视角，任何一条失败即测试不通过。
