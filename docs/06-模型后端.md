# 模型后端：Claude / OpenAI / 兼容网关

三种后端走**完全相同的信息通道** —— 都只拿到 `PlayerView`，都要过 `actions.validate()`，
没有后门。可以按座位任意混搭（比如 1~3 号用 GPT-5、4~6 号用 Claude、其余规则 bot）。

| 后端 | 说明 | 密钥环境变量 | 模型名 |
|---|---|---|---|
| `heuristic` | 规则 bot，零依赖不花钱 | — | — |
| `claude` | Anthropic（`llm` 是它的旧名字，继续可用） | `ANTHROPIC_API_KEY` | 白名单校验 |
| `openai` | OpenAI **以及任何 OpenAI 兼容网关** | `OPENAI_API_KEY` | **任意字符串** |

---

## 1. 挂自己的 provider：三个参数

```
base_url  +  model  +  api_key
```

```bash
uv sync --extra openai

python3 run_game.py --backend openai \
    --base-url https://my-gateway.example.com/v1 \
    --model my-provider/llama-3-70b \
    --api-key sk-xxxxx
```

这三个参数**完全不依赖环境变量**。当然也可以用环境变量：

```bash
export OPENAI_API_KEY=sk-...
export OPENAI_BASE_URL=https://my-gateway.example.com/v1
python3 run_game.py --backend openai --model qwen-max

# 或者只说去哪个变量取（适合一局里挂多个不同的 provider）
python3 run_game.py --backend openai --model qwen-max \
    --base-url https://gw-b/v1 --api-key-env GW_B_KEY
```

官方 OpenAI 就是不填 `--base-url`：

```bash
python3 run_game.py --backend openai --model gpt-5 --api-key sk-...

# 混搭：1~3 号用 OpenAI，其余规则 bot
python3 run_game.py --backend openai --model gpt-5 --api-key sk-... --llm-seats 1,2,3
```

**网页沙箱**：座位的「后端」选 **OpenAI / 兼容网关**，模型可以从建议列表选，
也可以在旁边的框里**随便填**（自建网关的模型名五花八门，所以不做白名单）。
「高级选项」里有 **网关地址** 和 **API Key** 两个输入框。

没有可用的密钥时**开局会被直接拒绝**，并告诉你是哪几个座位 ——
而不是让你打到一半才发现每一手都在报错。

## 2. 密钥去了哪里

密钥**只活在内存里**。它要经过的每一个会被持久化或者被展示的地方，都是脱敏的。

阵容（`SeatSpec`）要写进会话库、还要回传给前端渲染，所以 `as_dict()` 里
**没有密钥本身**，只有一个「配没配」的布尔量：

```json
{"seat": 1, "backend": "openai", "model": "my-provider/llama-3-70b",
 "base_url": "https://my-gateway/v1",
 "api_key_env": "OPENAI_API_KEY", "api_key_set": true}
```

具体哪些地方脱敏了（都有测试盯着）：

| 位置 | 是否含密钥 |
|---|---|
| `config.json` / 会话库的 `games.lineup` | 否，只有 `api_key_set` |
| 服务端回传给浏览器的快照 | 否 |
| `agent_sessions`（会话存档） | 否 |
| `replay.md` / `events.jsonl` / `thoughts.json` | 否 |
| agent 对象的 `repr()` | 否，显示 `api_key=***` |

网页上的 API Key 输入框是 `type="password"`，而且**服务端不会把它回传**——
刷新页面之后要重新填。

**手滑保护**：最常见的错误是把密钥粘到了「密钥环境变量名」那一栏。
真这么干了会自动帮你挪到 `api_key`（而不是把密钥当成变量名去查，然后报一个看不懂的错）。

**一局挂多个 provider**：给不同座位填不同的 `base_url` + `api_key` 就行，
或者用 `api_key_env` 分别指向不同的环境变量。

## 3. 能力自动降级（为兼容网关准备的）

自建网关的能力参差不齐：有的支持严格 `json_schema`，有的只认 `json_object`，
有的两个都不认；有的要 `max_completion_tokens`，有的只认 `max_tokens`。

所以 OpenAI 后端会**自己试出能用的那一档，并且记住它**：

```
json_schema(strict)  →  json_schema(宽松)  →  json_object  →  纯文本
max_completion_tokens  →  max_tokens
```

- 只有"端点不支持某个参数"这类错误才会触发降级；
  **认证失败、余额不足、限流会直接抛出来**，不会白白重试
- 降到 `json_object` 或纯文本之后，协议层已经管不住格式了，
  所以会**把 JSON Schema 直接写进 prompt**，否则弱一点的模型会漏字段
- 返回的文本会用一个稳健的抽取器解析：直接 parse → 剥 markdown 代码块 →
  找第一个配平的花括号（字符串里的括号不会算错）
- 不管退到哪一档，最后都要过 `actions.validate()`，格式没守住也串不进游戏

实测（对着一个只支持 `json_object` + `max_tokens`、而且还会把结果裹进
` ```json ` 代码块的网关）：

```
协商出来的能力档位: mode=json_object  token 参数=max_tokens
报错/回退: 无
```

## 3.5 连不上的时候

引擎本身已经有 `max_iterations` 的重试循环了，所以 OpenAI 客户端默认
**不再叠加 SDK 自己的指数退避重试**（`max_retries=0`，`timeout=120s`）。
否则网关一挂，一局游戏会从"几秒钟报错"变成"卡上好几分钟"。

连不上会**立刻**报错，并且把地址原样说出来：

```
连不上 http://127.0.0.1:9/v1 —— 检查 base_url 是否正确、网关是否在跑。原始错误：Connection error.
```

## 4. 推理强度

`--effort` 对两个后端的含义不同：

- `claude`：走 `output_config.effort`，五档 `low/medium/high/xhigh/max`
- `openai`：映射成 `reasoning_effort`，只传 `low/medium/high`
  （更高的两档不传，避免非推理模型直接报错）；网关不认这个参数时会被降级逻辑接住

---

## 5. 两个后端共用的东西

`werewolf/agents/chat_base.py` 里放的是两边一样的部分，避免行为漂移：

- system prompt 整局逐字不变（命中 prompt cache）
- 每回合只发增量，但**发言档案和票型每回合完整重发**（见 `docs/04`）
- 历史裁剪
- 私人笔记本的读写（容器化时挂在比容器活得久的卷上）
- `private_thought` / `notes_update` 的处理

各自实现的只有 `_complete()` —— 怎么调 API、怎么约束输出格式。

---

## 6. 成本提醒

一局 12 人对局大约 **150+ 次模型调用**。先用 `--llm-seats 1,2,3`
或者在网页里只给两三个座位配 LLM 试水，确认剧本质量再放开。

规则 bot 不花钱，可以随便当陪练 —— 而且它也会输出心路历程，复盘照样好看。
