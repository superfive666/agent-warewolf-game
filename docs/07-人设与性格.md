# 人设与性格（草案）

> **状态：草案，待评审。** 评审通过后按本文 §12 分批实现；实现完成后删掉 §12，
> 剩下的部分作为正式规范保留，代码以本文为准。

---

## 1. 要解决的问题

同一个模型、同一份角色卡跑出来的 agent 太像了：

- **说话一样**：条理清楚、礼貌、复盘腔，套话重复，发言长度也差不多；
- **判断一样**：大家注意到同样的疑点，推出同样的结论，投票常常一边倒；
- **没有人性**：不记仇，不上头，不从众，不会因为被踩而急着自证，也不会记错号码；
- **打法一样**：`prompts.ROLE_STRATEGY` 给每个同身份的座位同一套「标准打法」，
  它本身就在把大家往同一个方向推。

现在唯一的差异来源是 lineup 里选了不同的模型或 effort；规则 bot 的差异只有几个写死的随机阈值。

**目标**：让每个座位都是「一个具体的人」，说话方式、判断倾向、水平、情绪各不相同，
而且这些差异**在对局里看得出来，统计上也测得出来**。

**不做**：

- 不改规则，不改胜负判定；
- 不做跨局记忆和名声系统（放在 §13 远期）；
- 不给真人座位强加人设。

---

## 2. 设计原则

1. **性格决定「怎么赢」，不决定「想不想赢」。** 所有人都想让自己的阵营赢。
   冲动型不是送局，是会在证据不足时就开车。
2. **行为锚点，不写形容词。** 「你很暴躁」没用：LLM 要么演成漫画式的角色，要么几轮后回到默认腔调。
   要写成「被人踩的时候你会……」「你从来不说……」，再配 2~3 句示范发言。
3. **能用机制约束的，不只靠 prompt。** 发言长度、看得到多少信息、规则 bot 的阈值，
   这些都直接由参数决定。prompt 只负责机制管不到的「味道」。
4. **人设独立于身份。** 人设在发牌之前、用独立的随机流分配，和身份无关。
   否则人设本身就泄露身份。
5. **不开人设时，行为和现在逐字一致。** 所有改动都要能退化回当前版本。

## 3. 人设模型

一个人设由五层组成：

```jsonc
{
  "id": "hothead",                     // 内部标识符，英文
  "name_cn": "暴躁老哥",                // 显示名
  "intensity": "medium",               // light | medium | heavy：演得多重

  // ① 公开层：桌上其他人「平时就知道」的印象（是否公开见 §5）
  "public": {
    "tagline": "有话直说，别绕弯子",      // 开局自我介绍的一句话
    "style_tags": ["直球", "嗓门大"]
  },

  // ② 表达层：只影响 speech 字段怎么写
  "voice": {
    "verbosity": 0.6,                  // 0~1，决定每个座位的字数上限（§7.1）
    "tone": "冲，爱用反问句，情绪外露",
    "catchphrases": ["我就问一句", "别跟我扯"],
    "taboos": ["不说「表水」「以上」这类套话", "不写一二三分点"],
    "samples": [                       // 2~3 句示范发言，定调用
      "3 号你别跟我扯什么逻辑，你昨天那票怎么投的你自己说！",
      "我就问一句，警上那么多人，你凭什么第一个踩我？"
    ]
  },

  // ③ 决策层：0~1 的倾向值
  "traits": {
    "aggression": 0.8,                 // 激进：多早开始踩人、归票
    "suspicion": 0.6,                  // 多疑：多容易怀疑别人
    "conformity": 0.3,                 // 从众：多容易跟票、跟站边
    "stubbornness": 0.7,               // 固执：站了边多难改
    "risk": 0.7,                       // 冒险：上警、起跳、悍跳、自爆的倾向
    "emotionality": 0.8                // 情绪化：被踩之后判断会变形多少
  },

  // ④ 认知偏差：从固定枚举里选 1~2 个
  "biases": ["RETALIATION"],

  // ⑤ 水平层
  "skill": "regular"                   // novice | regular | veteran
}
```

### 3.1 认知偏差枚举

| 标识符 | 显示名 | 表现 |
|---|---|---|
| `RETALIATION` | 报复心 | 谁踩过我，我就更怀疑谁、更愿意投谁 |
| `SUNK_COST` | 不愿认错 | 站了一个预言家的边，就很难再改 |
| `BANDWAGON` | 跟风 | 场上多数人倾向谁，我就倾向谁 |
| `FIRST_CLAIM` | 先入为主 | 更相信第一个跳身份的人 |
| `GUT_FEELING` | 凭感觉 | 看语气和状态，不太看逻辑链 |
| `FIRST_SPEAKER` | 首置位偏见 | 觉得首置位发言的人更可疑 |
| `VOTE_ONLY` | 只看票型 | 不太信发言，主要看投票记录 |

### 3.2 数值特质怎么变成文字

LLM 不擅长理解「aggression = 0.8」。渲染 prompt 时按三档（低 < 0.35 ≤ 中 ≤ 0.65 < 高）
映射成固定的中文句子，例如：

- `conformity` 高：「场上多数人倾向谁，你会不自觉地跟过去；你很少当第一个投反对票的人。」
- `conformity` 低：「你不太在乎别人怎么想，全场都投 A，你照样可以投 B。」

同一组数值总是渲染成同一段文字（system prompt 整局不变，见不变量 #10）。

## 5. 分配与可见性

### 5.1 分配

- `SeatSpec` 新增字段 `persona`，取值：
  - `""`：不用人设（默认，行为和现在一样）；
  - `"random"`：从库里随机抽；
  - 某个 `id`：指定人设。
- 在 `new_game()` 发牌**之后**，用独立的随机流分配：
  `random.Random(f"persona:{config.seed}")`。这样**开不开人设，同一个种子发出来的牌都完全一样**。
- 随机抽取默认不放回（同一局里不重复），库不够用时再允许重复。
- 分配结果写进 `Player.persona`（上帝视角的状态）和会话库的 lineup。
- 真人座位不分配私有人设。

### 5.2 可见性（沿用 events.py 的四层）

| 内容 | 本人 | 其他玩家 | 狼队友 | 上帝 / 复盘 |
|---|---|---|---|---|
| 公开层（tagline、style_tags） | ✓ | ✓（开关控制） | ✓ | ✓ |
| 表达层 / 决策层 / 偏差 / 水平 | ✓ | ✗ | ✗ | ✓ |

- `identity` 新增 `persona` 字段：只有自己的完整人设。
- 新配置项 `GameConfig.persona_public`（默认 `true`）：打开时，
  `_PublicPlayer` 投影新增 `persona_tag`（只含公开层），开局追加一条 PUBLIC 事件
  「各位玩家的自我介绍」。`_PublicPlayer` 仍然**没有 `role` 属性**。
- 狼队视角**不**包含队友的私有人设。队友平时什么风格靠公开层和发言去判断，和真人一样。

### 5.3 人设通过视角传给 agent

agent **从 `view.identity["persona"]` 读人设**，不走构造函数或环境变量。好处是：
subprocess / docker / k8s 三种运行时走的 HTTP 契约不用改，`agent_server.py` 也不用新增环境变量，
人设天然跟着视角走。

## 6. 对 prompt 的影响

### 6.1 system prompt（整局不变）

在「你的身份」和「打法提示」之间插入一节：

```
════════ 你这个人 ════════
你在牌桌上是个「暴躁老哥」式的玩家。
说话：冲，爱用反问句，情绪外露。口头禅：「我就问一句」「别跟我扯」。
你从不：说「表水」「以上」这类套话；写一二三分点。
你说话大概是这样的：
  「3 号你别跟我扯什么逻辑，你昨天那票怎么投的你自己说！」
倾向：……（§3.2 渲染出来的几句）
你的毛病：谁踩过你，你就更想投谁。
注意：这些是你打牌的风格，不是让你故意输。你仍然全力为自己的阵营赢。
你拿到狼的时候，要尽量保持平时的说话风格——风格突然变了，别人会看出来。
```

不开人设时这一节整段不出现，system prompt 和现在逐字一致。

### 6.2 拆分 `ROLE_STRATEGY`

把现在的打法提示拆成两部分：

- `ROLE_BASICS[role]`：规则层面的认知（比如「女巫首夜通常用解药」「后置位有利」），所有人都拿；
- `ROLE_STYLE[role][axis]`：风格化打法，按人设的 `aggression` / `risk` 取对应的一档。
  例如预言家：激进档是「第一天就跳，直接报查杀」，保守档是「藏一两轮，等拿到更多信息再跳」。

`skill = novice` 只拿 `ROLE_BASICS`，也不拿 `POSITION_NOTE`。
**不开人设时继续用现在的 `ROLE_STRATEGY` 原文**，不做拆分后的拼接。

### 6.3 user 消息（每回合）

- 在「合法动作」前面加一行人设提醒（从人设渲染出来的一句话，≤ 40 字），防止长局后人设漂移；
- 发言类动作额外提示本座位的字数上限和建议长度（§7.1）。

### 6.4 输出字段不变

不新增 schema 字段。`private_thought` 仍然只进 GOD 层（不变量 #3）。

## 7. 机制层约束

### 7.1 每个座位单独的字数上限

- 上限 = `round(config.max_speech_chars × f(verbosity))`，`f` 把 0~1 线性映射到 0.25~1.0。
  闷葫芦大约 110 字，话痨就是全局上限 450 字。
- 建议长度 = 上限的 60%，写进 prompt。
- `actions.legal_actions()` 按座位下发 `max_chars`，`_check_length()` 按座位校验。
  超出上限时打回重说的机制不变。
- 真人座位和不开人设的座位继续用全局上限。

### 7.2 水平层：用信息量区分，不靠 prompt

LLM 很难「故意打差」，让它演新手，它会一边写出完美的逻辑一边说「我不太懂」。所以：

| 水平 | 发言档案 | 打法提示 | 私人笔记本 |
|---|---|---|---|
| novice | 只重发当天和前一天的发言，更早的只保留「谁跳了什么身份、谁出局」 | 只有 `ROLE_BASICS` | 有 |
| regular | 完整发言档案（现状） | BASICS + STYLE | 有 |
| veteran | 完整发言档案（票型现在就是全量给的，这一档不再加信息，只加打法提示） | BASICS + STYLE + `POSITION_NOTE` | 有 |

裁剪只会**减少**视角里的信息，不会带来新的泄露。裁剪在 `prompts.turn_prompt()` 里做，
`PlayerView` 本身不变，视角测试不受影响。

### 7.3 规则 bot 参数化

`HeuristicAgent` 在第一次 `act()` 时从视角读出人设，用 traits 替换写死的常数：

| 现在 | 改成 |
|---|---|
| 上警概率 0.4 / 0.3 / 0.35 | 基准值 × (0.5 + `risk`) |
| 自爆概率 0.45 | 基准值 × (0.5 + `risk`) |
| 怀疑度噪声 `rng.random() * 0.2` | 噪声幅度随 `GUT_FEELING` / `suspicion` 变化 |
| 跟随「相信的预言家」投票 | 按 `conformity` 混入场上多数人的票 |
| — | `RETALIATION`：踩过我的人怀疑度加分 |
| — | `SUNK_COST`：`believed_seer` 改站边的门槛随 `stubbornness` 提高 |
| 发言模板 | 按 `verbosity` 截取句子数，按人设插入口头禅 |

不开人设时所有系数取中性值，行为和现在完全一致（同一个种子、同样的结果）。

### 7.4 不调采样温度

Claude 开 extended thinking 时温度必须是 1，OpenAI 的推理模型也不支持调温度，
所以不把温度当作人设参数。模型本身的多样性交给 lineup 里的「混搭模型」。

## 8. 动态状态：情绪和关系

在私人笔记本的约定里加一个固定小节「关系表」，prompt 要求 agent 每回合维护：

```
## 关系表
3号：昨天踩过我，火大 😠 怀疑度↑
7号：一直帮我说话，信任
## 状态
被两个人连续踩，有点上头
```

- 这只是 prompt 约定，笔记本机制本身不变（仍然只有自己看得到）；
- 没有挂 memory 目录的 in-process 座位，笔记本改为存在内存里，
  这样人设在所有部署模式下表现一致（需要同步更新 `docs/05-部署与会话存储.md`）；
- 规则 bot 用内部的字典记同样的信息，给 `RETALIATION` 等偏差使用。

## 9. 前端与接口

视觉设计已经定稿，只用现有组件加字段，不改设计：

- **配置页**：每个座位加一个「人设」下拉（无 / 随机 / 11 个人设），加一个「全部随机」按钮；
  加开关「公开玩家风格」对应 `persona_public`。
- **对局页**：座位卡在名字下方显示公开层的风格标签（仅 `persona_public` 打开时）。
- **上帝视角 / 复盘**：显示每个座位的完整人设，复盘结算表加一列「人设」。
- **历史对局**：lineup 里带人设，回放时照常显示。
- **接口**：`/api/options` 返回人设库（只含 id、显示名、一句话、公开层，供下拉用）；
  新字段都在 `tests/test_api_redesign.py` 里加断言。
- 有真人座位的对局在结束前，接口只返回公开层（沿用不变量 #4 的 403 / 过滤逻辑）。

## 10. 评估

改完要能用数据说明「人设起作用了」，而且没有破坏平衡：

| 指标 | 算法（全部零依赖） | 期望 |
|---|---|---|
| 各人设胜率 | `werewolf --games 200 --personas random -q` 按人设 × 阵营分组输出 | 没有明显碾压或垫底的人设 |
| 阵营胜率 | 同上 | 好人胜率仍然在 38% 左右 |
| 发言长度差异 | 每个座位发言字数的均值和方差 | 座位之间明显拉开 |
| 用词重合度 | 座位两两之间字符二元组的 Jaccard 相似度 | 开人设后下降 |
| 投票独立性 | 座位两两之间投票一致率 | 开人设后下降，但不能乱投 |
| 身份不泄露 | 只用「人设 + 发言长度 + 投票特征」猜身份，准确率和基线比 | 不明显高于基线 |

LLM 局的指标由一个离线脚本 `werewolf-eval` 从会话库里算，不打 API。
